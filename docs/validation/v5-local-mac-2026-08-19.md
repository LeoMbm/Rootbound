## Guided-connect acceptance added afterward

After the core green run, V5 gained the guided one-command `rootbound connect .` onboarding flow. Real-machine Mac acceptance has now demonstrated the following behavior on that newer branch state:

- plain `rootbound connect .` successfully reuses the configured OpenAI tunnel;
- an already exact-trusted project does not prompt for trust again;
- the supervised tunnel runtime reaches `running`;
- a second project can be opened with the same single `rootbound connect .` command;
- switching from project A to project B automatically stops the previous supervised runtime and starts the new one;
- no manual `rootbound stop` is required between projects;
- both trusted projects remain registered durably in SQLite;
- `rootbound status` reports two registered projects while one runtime is active;
- the CLI reports `Switched from: <projectRef>` when the active project changes.

During this acceptance pass, two daily-driver bugs were found and fixed:

1. switching projects originally required a manual stop because the supervisor refused a different `projectRef`;
2. the CLI error handler could mask a normal error with `ReferenceError: Cannot access 'CliUsageError' before initialization`.

A local no-network regression test now covers runtime switching between two projects and CLI error handling.

## Earlier bugs found and fixed

The first full Mac pass exposed several path-identity bugs caused by macOS aliases such as `/var/...` resolving to `/private/var/...`. These were fixed in project refs, exact-root workspace trust, undo/redo mutation paths, and construction-tool scope checks.

The validation flow was also hardened so syntax validation runs before the V5 test suite.

Real-machine checks also demonstrated exact-root trust, `doctor` status `ok`, model-free `self-test` read/command/write cleanup, project registry persistence, and a supervised tunnel runtime reaching `running`.
